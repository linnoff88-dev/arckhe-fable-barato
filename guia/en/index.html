In brief

Fable 5.2 is Anthropic's most capable and most expensive model: each input and output token costs twice as much as Opus. If you use Claude Code with a subscription, you burn through your Fable limit much faster than you think because some work runs on models you didn't choose. Anthropic published a document explaining where that cost comes from and how to cut it. This guide shows what the document says, what we measured in practice, and fable-barato: a free kit you can install in one minute in Claude Code.

The document

What Anthropic itself wrote

These are three public, official pages. Nothing was leaked: they're on Anthropic's website, but almost no one has read them. Below are the key excerpts, translated, with a link to each one.

OFFICIAL DOCUMENT · ANTHROPIC

1. Optimizing for cost and intelligence

platform.claude.com · Optimizing for cost and intelligence

“For most agentic work, start with Claude Opus 5.5 at the default effort level (medium).”
“Use Claude Fable 5.2 for demanding reasoning and long-running agent work, or when your tests with Opus 5.5 at higher effort still aren't enough.”
In a web research test (DeepResearch Bench II, default effort): “Claude Fable 5.2 cost 2.9 times as much as Claude Opus 5.5, with a score 1.9 points lower.”That's just one research test. For long, difficult work, the same document says Fable can go further.
On splitting work between a lead model and cheaper helpers: it came out ahead in only two cases—routine work with a “long cost tail” (most parts are cheap, and a few cost much more) and work larger than a context window (more than the model can read at once). “When the work is a chain of dependent steps, or fits in a single context without a long cost tail, the solo lead model at lower effort came out ahead in every measured case.”Measured on earlier models, as the document itself notes.
Running at low effort and retrying only what failed at high effort solved about 97% of tasks for US$ 0.17 each. Running everything at high effort: 95.3% for US$ 0.29.Opus 5.5, SWE-bench Pro (a benchmark for fixing bugs in real code).
Reviewing prompts with each new model saved 14% in both model transitions tested.
OFFICIAL DOCUMENT · ANTHROPIC

2. Create custom subagents (Claude Code)

code.claude.com · Subagents

The built-in search (Explore) uses “the main conversation's model.” When the conversation runs on Fable, Explore runs on Opus or stays on Fable, depending on the connection; with a Claude subscription, it runs on Opus.
“Your own subagent named Explore replaces the built-in one and keeps its own model field; set it to model: haiku to run searches on a cheaper model.”
A helper without the model field runs on the same model as the conversation that called it.
OFFICIAL DOCUMENT · ANTHROPIC

3. Choosing a Claude model and effort level in Claude Code

claude.com · Choosing a model and effort level in Claude Code

For routine work, both models get it right, and the larger one uses more tokens at a higher price. So “dropping to the smaller model for routine parts saves real money, with no quality cost.”
Fable “finished work that Opus and Sonnet couldn't handle at any effort level. It also costs more per token, which is another reason to save it for work that needs it.”
What we measured

I didn't take it on faith: I measured it

Everything ran in Claude Code with a subscription, in an isolated folder (without my settings), on 11/15/2026. Dollar amounts are the “API equivalent”: the cost Claude Code itself reports at the end of each run (total_cost_usd), calculated using the official price. With a subscription, you don't pay this in cash; it counts against your usage limit. “Effort” (low, medium, high) is how much the model thinks and checks before answering; you choose it with /effort.

1. File search, with and without the kit file

Fable 5.2 session. I asked Claude Code to find something in the code using built-in search. Twelve runs, six without the kit and six with it: eight on a simple search (in the public repository esforco-medido) and four on a heavy search in a private 29,000-line project.

Opus search (without the kit)US$ 0.05–0.12
Haiku search (with the kit)US$ 0.002

22× to 48× cheaper search (about 35 times on average), with the same correct answer in all 12 runs. Comparing each run without the kit to its counterpart with the kit, the search was 22 to 48 times cheaper. The entire session was 28% to 40% cheaper (average for each series), because the Fable portion itself doesn't change. You can repeat the simple search with the kit; the heavy search ran in a private project that isn't in the repository.

2. Does having Fable lead helpers pay off?

The same task done three ways, two runs each, scored by a checker the model can't see. Small task: fix a shopping cart (12 tests). Large task: fix 20 independent modules, each with one bug.

ApproachSmallLargeScore
Opus 5.5 alone (medium)US$ 0.19US$ 0.42maximum in all 4
Fable 5.2 alone (medium)US$ 0.46US$ 0.62maximum in all 4
Fable leading Sonnet helpersUS$ 0.83US$ 1.01maximum in all 4

Same score for all three. Leading helpers cost 1.6× to 1.8× as much as Fable alone and 2.4× to 4.4× as much as Opus alone, and generally took longer. Both tasks fit in one session, exactly the case where the document says splitting loses. We didn't test work larger than a context window, where the document says splitting may win.

An honest note: on the 20 modules, my checker marked 19 out of 20 in all six runs. The mistake was mine: one test expected “Back”, while the written rule says “Back”, which is what all six produced. I corrected the checker (note in the results).

What to do

Six rules for paying for Fable only where it's worth it

1. Start with Opus medium

That's the starting point Anthropic itself recommends. Increase effort before switching models.

2. Search with Haiku

An Explore file set to the Haiku model takes search off the expensive model. It was 22 to 48 times cheaper in our measurement.

3. Always set a helper's model

A helper (subagent) is a second copy of Claude that Claude Code starts to do part of the work. A helper without a defined model inherits the session's model. If the session uses Fable, even a helper that only reads files costs Fable rates.

4. Don't split what fits in one session

Leading helpers cost 1.6 to 4.4 times more for the same score. Split only when there are many independent parts and a lot to read.

5. Use Fable to judge, not for everything

Let Opus do the work and call Fable only to review what's critical. Don't overdo it: the document measured a strong model as an advisor and the gain was small, 1.7 points for about 2.1 times the cost.

6. Audit with every new model

Instructions written for an older model can make a newer one do extra work. Anthropic measured 14% savings from this review alone.

Technical section

The kit: for anyone who wants to install and measure

The technical section starts here: install, check, and repeat the measurements. You don't need this section to understand what came before.

What it is

Four pieces, one installer

🔎 agents/Explore.md

Replaces built-in search: read-only (Read, Glob, Grep), model: haiku, effort: medium.

🧭 rules/QUANDO-DIVIDIR.md

A block for your CLAUDE.md: default model, model for each helper type, when to split work, and the 5-item briefing.

🧐 agents/revisor-fable.md

Final review with Fable 5.2 (high), only when you ask for “fable review.” It doesn't edit anything: it points out blockers, what should change, and what's a suggestion.

🩺 /fable-barato skill

status checks the installation, auditar reviews CLAUDE.md, agents, and skills without changing anything, and dividir <tarefa> tells you whether the task is worth splitting.

Requirements

What you need

Claude Code

Tested on version 2.1.325, with a subscription (check with claude --version; to see each helper's model in /tasks, use 2.1.242 or later). The kit runs on Linux and macOS (bash).

Python 3 and git

The installer uses Python to add and remove the rules block without duplicating it. Measurements run only on Linux: they need rsync, timeout, and a login in ~/.claude/.credentials.json (on macOS, it's stored in Keychain).

Step-by-step guide

In 5 minutes

1

Download and install

Installs for your user (applies to all projects). If you already have an Explore.md or CLAUDE.md, it backs them up with the suffix .bak-fable-barato. Running it again won't duplicate anything.

# option A: for all your projects (~/.claude)
git clone https://github.com/linnoff88-dev/fable-barato ~/fable-barato
~/fable-barato/instalar.sh
# option B: for one project only (writes .claude/ and CLAUDE.md inside it)
cd ~/meu-projeto
~/fable-barato/instalar.sh --projeto
2

Check that search uses Haiku

Reopen Claude Code, ask it to search, then run /tasks right away: Explore should appear under Haiku. A helper that has finished stays on the list for only about 30 seconds.

# inside Claude Code
use Explore to find where function X is defined
/tasks
/fable-barato status      # table: Explore, agents without model, rules block, effort
3

Use it day to day

The CLAUDE.md rule already guides the model. The other commands are ready when you need them.

/fable-barato dividir "review the blog's 40 posts"   # worth splitting? which model?
fable review                                         # calls the revisor-fable on completed work
/fable-barato auditar                                 # audit without changes; applies only with "apply"
4

Undo

Removes the rules block, skill, and reviewer, and restores your old Explore.md, if you had one. The CLAUDE.md.bak-fable-barato copy is kept.

~/fable-barato/instalar.sh --desfazer                          # option A
cd ~/meu-projeto && ~/fable-barato/instalar.sh --desfazer --projeto   # option B
Kit level 2

maestro-roteador: choosing a model and effort for each task

The maestro is a skill that reads the task, finds the hardest step, and tells you which model and effort to use, including for each helper. Version 1.3 includes the Fable 5.2 rules from this guide. It chooses helper models automatically; for your current session, it makes a recommendation and you switch with /model and /effort.

git clone https://github.com/linnoff88-dev/maestro-roteador
cp -r maestro-roteador/skills/maestro-roteador ~/.claude/skills/
# in Claude Code: triage this: <your task>
Repeat the measurements

Measure in your project

The scripts run through your subscription in a temporary folder (they don't read your CLAUDE.md, hooks, or plugins). They use little of your limit: the search costs a few equivalent cents per run; the three approaches cost up to US$ 1 per run. Without PEDIDO, the search looks for something that exists only in the test project (esforco-medido: clone it and pass its folder to repeat our measurement); with GABARITO=arquivo.txt (one expected answer per line), the summary gives you the score.

cd ~/fable-barato/medicao
PEDIDO="Use the Explore subagent (do not search yourself) to find where X is defined. Reply only with path:line." \
  ./medir-explore.sh ~/meu-projeto 3 fable medium   # replace X with something from your project
./medir-3jeitos.sh tarefas/carrinho 2                 # Fable alone, Opus alone, Fable leading
./medir-3jeitos.sh tarefas/vinte-modulos 2
cat resultados/*/resumo.md
